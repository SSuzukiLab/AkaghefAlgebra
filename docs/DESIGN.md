# 設計思想 — なぜ三つの系列があるか

このライブラリには `Str` / `Pol` / `Vec` という三系列があり、どれも「代数の元」を
表現する。冗長に見えるが、三つは**非可換性の計算コストをどこで払うか**という
一点で異なっており、互いの代替にはならない。

このファイルは全体像と選択基準だけを扱う。各系列の詳細は
[series-str.md](series-str.md) / [series-pol.md](series-pol.md) /
[series-vec.md](series-vec.md) を参照。API とデータ構造の具体はコード側の責務なので、
ここには書かない（該当箇所をファイル:行で指す）。

## 三系列の対比

積が非可換であるという事実は、必ずどこかで代償を払って処理される。三系列は
その支払い場所が違う。

| | 元の表現 | 非可換性の代償 | 利用者が用意するもの | 次元 |
|---|---|---|---|---|
| **Str** | 語（生成元インデックス列）の線形結合 | **実行時の書き換え** | 生成元と関係式 | 無限可 |
| **Pol** | 指数ベクトルの線形結合 | **事前に解いた積公式** | 正規形と積公式 | 無限可 |
| **Vec** | 基底に対する係数配列 | **構造定数テーブル**（展開済み） | 基底と構造定数 | 有限のみ |

言い換えると、抽象度が下がるほど計算は速くなり、扱える代数のクラスは狭くなる。

- `Str` は**定義をそのまま入力する**。正規形は計算結果として出てくる。
- `Pol` は**正規形を先に人間が解いておく**。積は算術に落ちる。
- `Vec` は**全部展開して表にする**。構造は失われるが操作は完全に機械的になる。

## どれを選ぶか

- **関係式は与えられているが正規形を知らない** → `Str`。というより、これ以外に
  選択肢がない。生成元と関係式で定義された代数を最初に触るときは必ずここから。
- **正規形が分かっていて、速度か記号指数が要る** → `Pol`。特に指数を記号
  （`sym`）にできる点は `Str` では原理的に代替できない。$x^{\alpha}$ の無限族を
  一度に扱いたいならこちら。
- **有限次元で Hopf 構造を扱う** → `Vec`。双対代数・Drinfeld double・
  Heisenberg double・積分は構造定数の操作なので、この系列でのみ自動化されている。

迷ったら `Str` で書いて動かし、遅ければ `Pol` の積公式を導出する、という順序が
安全。`Pol` から入ると、積公式の誤りに気づけない（後述）。

## 系列間のつながり

```
  生成元 + 関係式
        │
        ▼
      [Str]  ────rep────►  [Str] (作用素の代数: StrEndV / StrWeylXQ)
        │                        │
        │                        │ act
        │                        ▼
        │                      [Pol]  (作用される多項式空間)
        │
        │ 有限次元表現 / 剰余
        ▼
      [Vec]  (構造定数)
```

- `rep` は `Str` から `Str` への準同型。行き先は多くの場合、作用素を語として持つ
  `StrEndV` や `StrWeylXQ`。
- `StrEndV` が二系列の橋になっている。作用素の**代数**としては `Str` の語だが、
  各作用素は「`Pol` の指数ベクトルに作用して係数を出し、指数をずらす関数」として
  実装されている（`Core/StrAlgebra/StrEndV.m` の `d`, `qth`, `xd` 等）。
  つまり $D_q$ や $q^{c\theta}$ の**実際の作用**はここに一箇所だけ書かれている。
- `Vec` は他の二つと直接つながっていない。有限次元の対象を独立に構成する系列。

## 全系列に共通する骨格

三系列は独立に見えて、同じ設計上の約束を共有している。ここを知らないと
どの系列も読めない。

- **元 = (係数, インデックス) の対**。`cf` が係数の縦ベクトル、`pw` が項ごとの
  インデックス。何をインデックスと呼ぶかだけが系列ごとに違う
  （語 / 指数ベクトル / 基底番号）。
- **正規化は明示的**。`calc` / `C` が「同類項を括る＋零係数項を削除する」。
  演算のたびに呼ばれる。
- **演算子オーバーロードの規約**（系列をまたいで一貫）:
  | 記号 | 意味 |
  |---|---|
  | `*` | 積 |
  | `\|` | テンソル積 |
  | `~` | 積評価（テンソル積因子を畳んで積にする） |
  | `&` | `~(a\|b)`。テンソルしてすぐ畳む |
  | `lb(x,y)` | Lie bracket $xy-yx$ |

  `|` は `+`, `-` より優先度が低いので括弧が要る。
- **係数体は Symbolic Math Toolbox の `sym`**。`NumericType` 列挙（`D`/`S`）で
  double と sym を切り替え、演算時に高い方へ昇格する。

## 係数の扱いに関する重要な注意

$q$ は `sym('q')` であり、**$\mathbb{Q}(q)$ を体として実装しているのではない**。
MuPAD の記号有理式として持ち、`simplify` で潰す。したがって:

- ゼロ判定は `isAlways(cf==0, Unknown="false")` + `simplify` であり、
  **決定手続きではない**。`simplify` が潰しきれなければ、本当は 0 の項が残る。
- double 経路では `abs(cf) > 1000*eps(cf)` という閾値判定になる。

つまり「関係式の検証が通った」は「`simplify` が潰せた」以上のことを主張しない。
恒等式の成立を厳密に主張したい場面では、この限界を明示すること。
