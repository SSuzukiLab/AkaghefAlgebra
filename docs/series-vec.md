# Vec 系列 — 構造定数

`Core/common/VectAlg.m` を中核とし、`Core/VectAlgebra/` の `DualAlg`,
`VectDrinfeldDouble`, `VectHeisenbergDouble`, `VectHomAlg`, `VectQuasiHopfAlg`、
および `Examples/VectAlgebra/` の具体例（`Uqsl2BorelSmall`, `SweedlerAlg`,
`CyclicGroupAlg`, `VectExtAlg` 等）が属する。

## 思想

**有限次元に落とし、構造をすべてテーブルにする。**

元は基底に対する係数の配列。積は 3 階テンソル（構造定数）、余積も同様。
$\mu, \eta, \Delta, \epsilon, S$ と積分・余積分を構造定数として登録すれば、
そこから先の操作は全部機械的な添字計算になる。

`Str` や `Pol` が「生成元と関係式」あるいは「正規形と積公式」という**構造の記述**を
保持しているのに対し、`Vec` はそれを捨てて**展開結果だけ**を持つ。情報を失う代わりに、
残った操作が完全に一様になる。

## この系列でしかできないこと

構造定数の上でしか定義できない操作が一群ある。

- **Hopf 公理の検証**（`verifyHopf`）。双代数の整合性・対蹠の公理を、
  テンソルの縮約として直接確かめる。
- **双対代数**（`DualAlg`）。積と余積を入れ替えるだけなので、構造定数表示では
  ほぼ自明な操作になる。生成元と関係式の表示からは自動で作れない。
- **Drinfeld double / Heisenberg double**。上と同じ理由で、この系列でのみ自動化
  されている。
- **積分・余積分**（`setIntegrals`, `verifyInt`）。有限次元 Hopf 代数に固有の概念で、
  そもそも無限次元では意味が変わる。

1 の冪根での small quantum group のように、**最初から有限次元である対象**を扱う
ときはこの系列が正解。

## 何を払うか

- **有限次元限定。** 包絡代数や量子群そのものは載らない。
- **メモリ。** 構造定数は次元の 2〜3 乗。`SparseEx`（`Core/tensor/SparseEx.m`）に
  よる疎表現でこれを緩和している。`VectAlg` が内部で `cf` を `SparseEx` に
  差し替えているのはこのため。
- **関係式が失われる。** 定義関係式が成り立つかを検証することはできない。
  `Str` の `checkRepresentation` に相当するものは存在しないし、原理的に作れない。
  構造定数が正しいかどうかは、構成した時点の議論でしか保証されない。

## 使い分け

同じ代数を `Str` でも `Vec` でも構成できる場合がある（有限次元なら常にそう）。
そのときは目的で選ぶ。

- 関係式が成り立つかを確かめたい、生成元レベルの計算をしたい → `Str`
- Hopf 構造の公理、双対、double、積分を扱いたい → `Vec`

両方を作って突き合わせられるなら、それが最も強い検証になる。

## 落とし穴

- `VectAlg` の `rank` も**テンソル階数**の意味。`Str` と同じ規約。
- 構造定数の登録時に添字の順序（`Nio` の指定）を間違えると、すべての計算が
  一貫して間違ったまま通る。`verifyHopf` を必ず先に走らせること。
- `Examples/VectAlgebra/` の具体例は $q$ を複素数値（1 の冪根）で持つものが多い。
  記号 $q$ のまま扱えるとは限らない。
